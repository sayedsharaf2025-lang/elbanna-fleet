# دليل التأمين وخطوات التشغيل

## الفكرة
- **المكتب**: الدخول عبر Supabase Auth. اسم المستخدم بيتحوّل لإيميل داخلي ثابت (`u<hash>@elbanna-fleet.app`). كلمات السر عند Supabase بس (bcrypt)، ومفيش أي سر في جداول التطبيق أو المتصفح.
- **السائق**: مالوش حساب ومابيلمسش الجداول. كل حاجة عبر Edge Function `driver-api` بتوكن موقّع (14 يوم)، والرقم السري (6–8 أرقام) متخزّن bcrypt مع قفل من السيرفر بعد المحاولات الخاطئة.
- **RLS**: بعد `security-02-lockdown.sql` الزائر (anon) ماعندوش أي وصول. الموظف المسجّل (له سجل نشط في `profiles`) بس بيقرا ويكتب.

## ترتيب التنفيذ
1. `sql/security-01-schema.sql` (آمن، مابيكسرش حاجة): جدول profiles + الدوال + ترحيل المستخدمين القدام.
2. نشر الدالتين: `supabase functions deploy admin-users driver-api --no-verify-jwt` (أو من لوحة Supabase).
3. ضبط الأسرار: `DRIVER_TOKEN_SECRET` (32+ حرف عشوائي) و`BOOTSTRAP_SECRET`.
4. أول تشغيل: من أي جهاز، استدعي `admin-users` بـ `action: "bootstrap"` والسر عشان تفعّل حساب الأدمن الأول (كلمة سر قوية ≥ 8).
5. بعد الأدمن، من شاشة المستخدمين اضغط **تفعيل دخول الكل** وسلّم كل مستخدم كلمته المؤقتة.
6. انشر التطبيق الجديد (ويب + APK الطلبات + APK السائق) وجرّب الدخول.
7. **آخر حاجة**: شغّل `sql/security-02-lockdown.sql` (النسخ القديمة من التطبيق هتبطّل تشتغل).

## ملاحظات
- غيّر فورًا أي كلمة سر ضعيفة قديمة (ah, ahmed, admin, sh).
- مفتاح `service_role` عمره ما يتحط في التطبيق.
- بعد أي تعديل في ملفات مشتركة: `npm run sync:functions` (و`npm run check:functions` في CI).
- اختبارات: `npm test` و`npm run test:sql` (محتاجة Postgres محلي).
